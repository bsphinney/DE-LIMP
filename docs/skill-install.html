UC Davis Proteomics Core · DE-LIMP

Analyze your proteomics data by asking Claude

This guide installs a skill that takes you from raw mass-spec files to a list of differentially expressed proteins — search, statistics, figures, and a written report — without you assembling a pipeline. It takes about five minutes to set up, and you only do it once.

ucdavis-proteomics-core-pipeline macOS · Windows · Linux No admin rights needed

What it does

You point it at a folder of raw files and describe your experiment in plain words. It handles everything else.

The skill works out whether your data is DIA or DDA and which instrument produced it, then takes the search parameters for that data type from the defaults shipped with the skill rather than inventing them. It installs its own search engine, fetches the right protein database for your organism, runs the search, and carries the results through differential expression analysis in limpa/limma.

What you get back is a folder with one self-contained HTML report (the written interpretation, QC, volcano plots, PCA and violins, all embedded), a results table per comparison, a publication Methods section in Markdown and Word, a package for depositing the data in PRIDE or MassIVE, and a reproducibility bundle that lets someone else re-run the exact analysis. It also audits your experimental design and stops if something is wrong — a group with no replicates, a batch confounded with your biology, or contamination that could masquerade as a real result.

Before you start

Three things. Nothing else needs installing — the skill sets up its own toolchain the first time it runs.

1. Claude, in one of two forms

Either Claude Code (runs in a terminal) or the Claude Desktop app. Both work; the install steps differ slightly and both are covered below. If you have neither and aren't sure which to pick, Claude Desktop is the gentler start.

If you're going the terminal route and don't have Claude Code yet, install it first:

macOS and Linux
curl -fsSL https://claude.ai/install.sh | bash
Windows, in PowerShell
irm https://claude.ai/install.ps1 | iex

Then run claude to start it, and claude --version if you want to confirm it's there.

2. Your raw mass-spec files

Bruker .d folders, Thermo .raw files, or .mzML. Keep them together in one folder. You do not need to convert or rename anything.

3. Two facts about your experiment

The organism (this determines the protein database, and it cannot be detected from the files), and which samples belong to which group. You can describe the groups in words or hand over a spreadsheet — whatever you already have.

Install the skill

One line in a terminal, two commands in Claude Code, or a few clicks. You do this once; it stays installed.

In Claude Code

The terminal version

Easiest, in a terminal: paste this one line whole, then start Claude Code (or run /reload-plugins if it is already open).

Add the source and install, in one line
claude plugin marketplace add https://github.com/bsphinney/DE-LIMP.git && claude plugin install ucdavis-proteomics-core-pipeline@ucdavis-proteomics-core

Or inside Claude Code: paste the first command, press Enter, then the second. Pasting both at once does not work.

Step one — add the source
/plugin marketplace add https://github.com/bsphinney/DE-LIMP.git
Step two — install
/plugin install ucdavis-proteomics-core-pipeline@ucdavis-proteomics-core

Claude will ask you to confirm before trusting a new plugin source. Accept it, and the skill is ready.

In Claude Desktop

The app, no terminal

Everything starts from the + button beside the prompt box:

  • Click +, then choose Plugins.
  • Choose Add plugin to open the plugin browser.
  • Add the marketplace bsphinney/DE-LIMP.
  • Find ucdavis-proteomics-core-pipeline and click Install.

To check on it later, take the same route and choose Manage plugins. The Customize item in the sidebar also reaches plugins, alongside skills and connectors.

Confirming it's there, and keeping it current

In Claude Code, /plugin list shows what's installed. Running /plugin on its own opens a browser with tabs for discovering plugins, managing the ones you have, and viewing any errors. If the skill doesn't respond in the session where you installed it, /reload-plugins activates it without restarting.

Updates do not arrive on their own. Claude Code leaves automatic updates off for a marketplace like this one, so an installed skill stays on the version you first installed until you update it. Turn them on once, right after installing: run /plugin, open Marketplaces, choose ucdavis-proteomics-core, and pick Enable auto-update.

To update now: run /plugin, open Installed, choose ucdavis-proteomics-core-pipeline, and pick Update now. Or, in a terminal:

Update the skill to the latest version
claude plugin update ucdavis-proteomics-core-pipeline@ucdavis-proteomics-core

Then run /reload-plugins, or restart Claude Code. Note that /plugin marketplace update only refreshes the list of available versions. The installed skill stays where it was.

If the update says “already at the latest version” while a newer release is out, or warns that the marketplace was not refreshed (seen on a Windows laptop with no GitHub SSH key), Claude Code could not refresh its copy of the catalogue and compared against the old one. Refresh it over HTTPS, then run the update again. Inside the skill, Claude does this for you at the start of a session.

Refresh the catalogue over HTTPS (Git Bash or a terminal)
git -C ~/.claude/plugins/marketplaces/ucdavis-proteomics-core pull --ff-only

Note the two different names: https://github.com/bsphinney/DE-LIMP.git is the GitHub repository you add, while ucdavis-proteomics-core is the marketplace inside it that later commands refer to. The repository is added by its HTTPS address because Claude Code tries SSH first for the short form bsphinney/DE-LIMP, and many laptops have no GitHub SSH key. If you added the short form before, keep it: the refresh above works for it.

Run your first analysis

There is no command to remember. Describe what you have, and the skill starts itself.

Say something like

“Analyze my proteomics data in ~/data/HeLa_treated. It's human — the first three files are control and the last three are treated.”

Phrases that also start it: search these raw files, find differentially expressed proteins, process this timsTOF run, or simply pointing at a folder and asking what's in it. It will then work through the following with you.

  1. 1

    It asks where you're running

    Whether you have a UC Davis HIVE account, and whether you're in the Proteomics Core. If you're neither — which is most people — say no to both and everything runs on your own machine. HIVE is a shortcut for Core members, never a requirement.

  2. 2

    It sets up its toolchain

    On the first run only, it installs R, the statistics packages, and a search engine into a single self-contained folder. This takes a few minutes and needs no admin password. Later runs skip it in seconds.

  3. 3

    It detects your data and confirms the plan

    It reads the files to determine DIA or DDA and the instrument, matches a validated workflow, and shows you what it intends to run. Nothing heavy starts without your explicit go-ahead — a search can run for hours, so it always asks first.

  4. 4

    It runs, watches itself, and fixes problems

    Once the search is going it monitors progress and recovers on its own from the usual failures — a job that runs out of memory, hits its time limit, or stalls on a bad file. You don't need to babysit it. It reports what it recovered.

  5. 5

    It checks the results before believing them

    Before writing anything up it audits the design and the data: too few replicates, a confounded batch, unusually low identification depth, or contamination that could look like biology. Warnings are surfaced to you, and genuine problems stop the analysis rather than producing a confident-looking wrong answer.

  6. 6

    It writes everything up

    Results land in a dated session folder next to your raw data (or anywhere else you ask). Open README.html inside it, then output/Analysis_Report.html.

Notes for your platform

Most people need none of this. Check only the row that matches you.

You're onWhat to know
Linux Everything installs and runs automatically. Nothing extra to do.
macOS DDA data and all statistics work out of the box. For DIA data, DIA-NN has no Mac build, so the skill runs it in Docker — you'll be asked once to install Docker Desktop and open it. That is the only manual step anywhere in this pipeline.
Windows Two routes. WSL2 (wsl --install) is smoothest — run the skill inside it and everything follows the Linux path. Native Windows also works, since the search engines ship Windows builds; run the skill from a POSIX shell such as Git Bash.
UC Davis HIVE Tell the skill you have an account and where your SSH key is. It drives HIVE from your laptop and submits searches as SLURM jobs — never on a login node. Core members additionally reuse the software already installed in the group directory.
Check this if you're not at a university

DIA-NN's free build is licensed for academic and non-profit use only. If you're in a commercial setting, say so when asked and the skill will route your DIA data to AlphaDIA (Apache-2.0) or Sage (MIT) instead. Both are free for commercial use.

If something goes wrong

The short version: tell Claude what you're seeing, in plain words. It knows how to repair its own environment. These are the few cases worth recognizing.

What you seeWhat to do
The skill doesn't start when you describe your data Confirm it's installed with /plugin list (or the plugins panel), and try /reload-plugins. If it is installed, name it directly: “use the ucdavis-proteomics-core-pipeline skill on this folder”.
Something about R, limpa, or a missing package Ask Claude to re-run the setup step. Don't install R or Bioconductor by hand — the skill manages its own environment, and a system R won't be the one it uses.
“Docker is missing” on a Mac with DIA data Install Docker Desktop, open it once so the whale icon settles in the menu bar, then tell Claude to continue.
It can't find a protein database for your organism Any organism is supported: the organism only picks the database, never a search parameter. If UniProt has no proteome for it, the skill also looks in NCBI genome assemblies, or you can give it your own FASTA file.
It stops and refuses to interpret your results Read what it says carefully. It stops on designs it can't analyze honestly, such as a group with no replicate or contamination confounded with your comparison. This is the skill working, not failing.

Turning it off or removing it

To switch the skill off without removing it, use /plugin disable ucdavis-proteomics-core-pipeline@ucdavis-proteomics-core (enable brings it back). To remove it entirely, uninstall from the same plugin panel you installed it in.

To also remove the toolchain it installed, delete the folder ~/.proteomics-pipeline/. Nothing was installed system-wide, and your data and results are untouched.
