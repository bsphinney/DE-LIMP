How the Report Was Made

The analysis report you received, and its audio discussion if it has one, were produced with Claude, Anthropic's AI model, following a set of written instructions and scripts the Proteomics Core maintains. This page explains which parts were done by established proteomics software, which parts an AI wrote, which AI models were involved, and how your lab could run the same pipeline.

The short answer

Software

The numbers come from standard tools

DIA-NN (DIA data) or Sage (DDA data) searched the raw files. R packages, usually limpa and limma, did the quantification and statistics; each report names the ones it used. Every number in the report comes from these, and the statistics can be re-run as plain R with no AI involved.

Claude

Claude ran the tools and wrote the words

Claude, working in Claude Code, ran each step, read the tables and figures, and wrote the report text and, when there is one, the podcast script. Separate Claude reviewers check the podcast script, and the analysis too when it calls for an expert review.

Gemini

Google's Gemini makes the voices

When a report has a podcast, Gemini's speech model usually reads the script aloud in two synthetic voices. A second Gemini model then transcribes the audio back, so a script can confirm that every number was spoken correctly. If you would rather not use Google, a local voice can make the podcast instead (see below). Each report's "How this report was made" section says which voice made its podcast.

Step by step

The pipeline is a Claude Code "skill": a written procedure with dozens of helper scripts, which Claude follows in order.

Software established tools and the skill's scripts Claude written or reviewed by an AI Gemini Google's cloud models Local the voice option that stays on campus

  1. Read the raw files

    Scripts open the instrument files and work out the acquisition (DIA or DDA), the instrument and the m/z range. The search settings are derived from those, then confirmed once with the person running it.

    Software

  2. Search the spectra

    DIA-NN 2.7.0 (DIA data, library-free, 1% FDR, match-between-runs) or Sage (DDA data). At the Core this runs as jobs on UC Davis's HIVE computing cluster.

    Software

  3. Quantify and test

    limpa estimates each protein's amount and models missing values through a detection-probability curve instead of dropping or imputing them. limma tests each comparison with Benjamini–Hochberg FDR. Re-tests on complete data and with per-group variance flag which hits are robust. For a non-model organism, protein names come from DIAMOND searches against Swiss-Prot.

    Software

  4. Audit for common mistakes

    A script checks the results for known pitfalls: too few replicates, a confounded design, mixed instruments, low depth, heavy missingness, contamination, unstable normalisation, implausibly large or empty results. Anything it finds goes into the report's "Audit & caveats" section.

    Software

  5. Write the report

    Claude reads the tables, figures and audit, then writes the text: the overview, answers to the lab's own questions, findings per comparison, the biological interpretation and the methods. A script assembles it with the figures into one HTML file.

    Claude

  6. Expert review

    When a statistical claim goes to a collaborator, a result looks extreme (log2FC above 5, p below 10−10) or the organism is new, three separate Claude agents review the analysis independently, as a proteomics expert, a biologist and a statistician. Their points become the "Expert Review Notes" section.

    Claude

  7. Write the podcast script

    Once the report is final, Claude writes a conversation between two fictional hosts, a cell biologist and a statistician. It covers the results, how the samples were measured, and the key terms. Anything said that is not in the report is listed at the end of the transcript.

    Claude

  8. Check the script

    A script compares every number, gene-like symbol and capitalised name in the script with the report, and fails anything it cannot find. A separate Claude agent, not the one that wrote the script, then reads each sentence for overstatement and claims the robustness checks do not support.

    SoftwareClaude

  9. Make the voices

    Gemini's speech model reads the checked script in two voices (Kore and Charon). Only the transcript text is sent to Google. The report, tables and figures are not.

    Without Gemini, the open-source Kokoro model reads it instead, on the HIVE cluster, and nothing leaves campus.

    Geminior Local

  10. Listen back

    A Gemini text model transcribes the finished audio, and a script compares the transcript with the script. It warns if the word match falls below 0.93 (1 is perfect), if six or more words in a row were not heard, or if a number was not heard as written.

    For the local voice, two Whisper speech-recognition models on HIVE do the listening, and a misreading counts only where both hear it.

    Geminior LocalSoftware

  11. Package it

    One HTML file with the figures built in, so it opens offline; when there is a podcast, a second copy has the audio and the transcript built in too. Alongside it go a PDF, the tables and a reproducibility bundle: a pinned software environment, the R session details, checksums, a reproduce.sh and the whole statistical analysis as one plain R script.

    Software

Rather not use Gemini?

The podcast does not have to go through Google. The Core tested three free speech models that run on its own cluster against Gemini, by reading the same passage and checking every protein name and number. Kokoro was the only one that got all 13 numbers and all 11 names right, matching Gemini. The other two, VibeVoice and Qwen3-TTS, changed data numbers and were rejected.

Skill 2.14.0, released on 22 October 2026, builds Kokoro in two ways. Ask for it with --tts local and Gemini is never contacted. And when Gemini cannot be used (no key, credits used up, every model out of quota or not answering), the skill switches to Kokoro by itself and re-makes the whole episode, so the voices never mix. How the AI-written text is kept honest

An AI can write a fluent sentence that is wrong. The pipeline is built around that risk.

The AI does not make the numbers

Claude runs the tools and reports their output. It does not compute statistics itself. The plain R script in the bundle re-creates every statistical result without Claude.

Every hit is re-tested

Each significant protein is tested again on complete data only, and again with each group allowed its own variability. The report leads with the hits that survive both.

Independent reviewers

The expert reviewers and the podcast's meaning check are separate Claude agents, not the one that wrote the text, so they do not share its assumptions.

Claude writes the script, a tool checks it

An early version let a model write the podcast straight from the report. It passed a number check yet still invented facts, such as calling limpa "our Core's custom extension to limma". Now Claude writes the script from the report it has read, and a script checks every number and name against the report.

What the checks cannot catch

The checks find invented numbers and names, not every wrong sentence. That is why the report and the audio both say the written report is the record. The audio is a guide to reading the report, not a replacement for it.

Running it in your lab

The skill is public and free to install. It is maintained by the UC Davis Proteomics Core and written for biologists: it installs its own tools without administrator rights, and confirms the plan with you before the long steps.

  1. Get Claude Code

    Anthropic's Claude Code runs on your own computer and needs a Claude subscription or an Anthropic API key.

  2. Install the skill

    In a terminal, one line, then start Claude Code:

    claude plugin marketplace add https://github.com/bsphinney/DE-LIMP.git && claude plugin install ucdavis-proteomics-core-pipeline@ucdavis-proteomics-core

    Source and documentation: github.com/bsphinney/DE-LIMP, folder skill/ucdavis-proteomics-core-pipeline. Current release 2.14.1.

  3. Ask in plain words

    Point Claude at a folder of raw files, for example:

    Analyze the proteomics data in /data/my_experiment. It's mouse liver, knockout vs wild type, four of each.

    Claude checks the files, asks about the organism and design, confirms the search settings once, then runs the search, statistics, figures, audit and report.

  4. Add the podcast, if you want it

    It is optional and offered once the report is done. You choose the voice:

    • Gemini: you need your own Gemini API key. For unpublished data, use a key with billing turned on: under Google's Gemini API terms, free-tier content may be used to improve Google's products and read by human reviewers, and paid-tier content is not used that way.
    • Kokoro, the local voice (skill 2.14.0; for now Core members on HIVE): --tts local. No key, no consent form, nothing sent anywhere (details above).
    • macOS say: --tts say makes the audio offline with the Mac's built-in voices; it sends nothing, but nothing checks it automatically either.

    Cost: Google charges by length of audio. At the price checked on 16 October 2026, a 22-minute episode with Gemini 3.8 Flash TTS came to about 30 cents.

Where your data goes

  • Raw files are searched on your own computer or cluster. The files themselves are not sent to any AI service; Claude sees the scripts' summaries of them.
  • Claude sees what it reads while working: results tables, figures, logs and the report. Those go to Anthropic under the terms of your Claude plan. Check your institution's guidance for unpublished data.
  • Gemini receives only the podcast transcript, and then the audio for the listen-back check, and only if you make a podcast with Gemini voices. With the local voice or macOS say, nothing goes to Google.
  • Everything is recorded: each run keeps a log of the commands, the software versions and which models made the audio, so you can say exactly what was done.
